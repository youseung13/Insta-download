# 공개 게시물 다운로드 웹앱 (폰에서 어디서든 사용)

인스타그램·유튜브 등에서 **공개(로그인 없이 누구나 볼 수 있는) 게시물/영상**을 폰 브라우저로
바로 다운로드하는 간단한 웹앱입니다. URL만 붙여넣으면 서버가 yt-dlp로 받아서 파일을
폰에 다운로드해줍니다.

## 주요 기능
- **홈 화면 앱처럼 설치(PWA)**: "홈 화면에 추가"하면 주소창 없는 전체화면 앱처럼 열립니다.
- **최고화질 다운로드**: 영상+음성을 최고화질로 각각 받아 합칩니다.
- **MP3(음성만) 추출**: 영상 대신 음성 파일만 받을 수 있습니다.
- **캐러셀(여러 장) 게시물 전체 다운로드**: 사진/영상이 여러 개인 게시물은 전체 항목을
  zip 파일 하나로 묶어서 내려받습니다.
- **다운로드 전 미리보기**: 받기 전에 제목/썸네일을 먼저 확인할 수 있습니다.
- **콜드스타트(잠들었다 깨는 지연) 완화용 상태확인 경로(`/healthz`)**: 외부 핑 서비스로
  주기적으로 호출해 서버가 잠들지 않게 할 수 있습니다 (아래 4번 참고).

**이 도구가 하지 않는 것**
- 비공개 계정, 스토리 등 로그인이 필요한 콘텐츠는 지원하지 않습니다.
- 본인 콘텐츠 백업, 저작권/초상권 문제가 없는 용도로만 사용하세요.

---

## 1. 로컬에서 먼저 테스트 (선택)

```
pip install -r requirements.txt
python app.py
```

브라우저에서 `http://localhost:8000` 접속. (같은 와이파이의 폰에서 테스트하려면
PC의 사설 IP로 `http://192.168.x.x:8000` 접속)

---

## 2. 어디서든 접속되게 Render.com에 배포하기

무료 플랜(카드 등록 불필요)으로 충분합니다. 다만 15분간 안 쓰면 서버가 잠들고,
다시 접속하면 깨어나는 데 30~60초 정도 걸립니다 (아래 4번의 핑 설정으로 이 지연을
없앨 수 있습니다).

### (1) GitHub에 코드 올리기
1. github.com에서 새 저장소(Repository)를 만듭니다. (Private으로 만들어도 됩니다)
2. 이 폴더의 파일/폴더를 **전부** 그 저장소에 올립니다:
   - `app.py`, `requirements.txt`, `Dockerfile`, `README.md`
   - **`static` 폴더 전체** (`manifest.json`, `icon-192.png`, `icon-512.png`, `sw.js`) — PWA(홈
     화면 앱) 기능에 꼭 필요합니다.
   - GitHub 웹사이트에서 "Add file → Upload files"로 올리세요. 파일을 여러 개 한 번에
     끌어다 놓을 수 있고, `static` 폴더째로 끌어다 놓으면 폴더 구조가 그대로 유지됩니다.
   - **주의**: 모바일에서 파일 내용을 복사/붙여넣기로 편집하면 중간에 잘려서 저장되는
     문제가 있었습니다. 항상 "Upload files"로 실제 파일을 올리는 방식을 사용하세요.
   - 폰에 같은 이름의 파일을 다시 받으면 `app-2.py`처럼 자동으로 다른 이름이 붙을 수
     있으니, 올리기 전에 파일 이름이 정확한지(`app.py`, `Dockerfile` 등) 확인하세요.

### (2) Render.com에서 배포
1. https://render.com 에서 가입 (GitHub 계정으로 가입하면 편합니다)
2. 대시보드에서 **New + → Web Service**
3. 방금 만든 GitHub 저장소를 선택
4. Environment가 자동으로 **Docker**로 인식됩니다 (Dockerfile이 있어서)
5. Instance Type은 **Free** 선택
6. "Environment Variables"에서 다음을 추가합니다:
   - `APP_PASSWORD`: 원하는 비밀번호. **꼭 설정하세요.** 설정하지 않으면 이 URL을 아는
     누구나 내 서버를 써버릴 수 있습니다.
   - `IG_COOKIES_TXT` (선택): 인스타그램 429(요청 차단)가 자주 뜨면, 본인 인스타그램
     계정의 로그인 쿠키(Netscape 형식 cookies.txt 전체 내용)를 넣어두면 줄어듭니다.
7. **Create Web Service** 클릭 → 2~5분 기다리면 빌드/배포 완료
8. 완료되면 `https://무언가.onrender.com` 형태의 URL이 생깁니다

### (3) 폰에서 사용 + 홈 화면 앱으로 설치
1. 그 URL을 폰 브라우저로 접속 → 비밀번호 입력
2. 홈 화면에 추가하면 이제 **주소창 없는 전체화면 앱**처럼 열립니다 (manifest.json +
   아이콘이 적용됨):
   - iOS Safari: 공유 버튼 → "홈 화면에 추가"
   - Android Chrome/Edge: 메뉴(⋮) → "홈 화면에 추가" 또는 "앱 설치"
3. 다운로드하고 싶은 공개 게시물 URL을 붙여넣고, 필요하면 "미리보기"로 제목/썸네일을
   먼저 확인
4. 영상 그대로 받을지, MP3(음성만)로 받을지 선택
5. "다운로드" 탭 → 브라우저가 평소처럼 파일을 다운로드합니다 (다운로드 폴더에 저장됨)
   - 캐러셀(여러 장) 게시물은 `.zip` 파일로 받아져서, 압축을 풀면 안에 사진/영상이
     전부 들어있습니다.

## 3. (선택) 비공개 요청 줄이기 — 본인 인스타 계정 쿠키 등록

인스타그램이 로그인하지 않은 요청(특히 서버/클라우드에서 오는 요청)을 자주 차단
(429 Too Many Replicas)합니다. 본인 인스타그램 계정으로 로그인한 쿠키를 서버에 등록하면
요청이 로그인된 것처럼 나가서 차단이 줄어듭니다.

1. 폰에서 Microsoft Edge 같은 확장 프로그램 설치가 가능한 모바일 브라우저로 인스타그램에
   로그인
2. "Cookie-Editor" 확장 설치 → instagram.com 페이지에서 Export → Netscape 형식으로 내보내기
3. 내보낸 내용 중 `instagram.com` 관련 쿠키만 복사 (다른 사이트 쿠키는 포함하지 말 것)
4. Render 대시보드 → 해당 서비스 → Environment → `IG_COOKIES_TXT` 값으로 붙여넣기 → 저장
   (저장하면 자동 재배포됩니다)

**참고**: 이 쿠키는 보통 몇 주~몇 달 뒤, 또는 인스타그램 비밀번호를 바꾸거나 전체
기기에서 로그아웃하면 만료됩니다. 그러면 429가 다시 잦아질 수 있는데, 그때는 위 과정을
반복해서 `IG_COOKIES_TXT` 값을 새 쿠키로 갱신하면 됩니다.

## 4. (선택) 콜드스타트(잠들었다 깨는 지연) 없애기 — 무료 핑 서비스 등록

Render 무료 플랜은 15분간 요청이 없으면 서버가 잠들고, 다음 요청이 올 때 깨어나는 데
30~60초가 걸립니다. 외부에서 주기적으로 핑(ping)을 보내주는 무료 서비스를 쓰면 서버가
계속 깨어있게 만들 수 있습니다. (워커 1개가 계속 떠 있어도 월 750시간 무료 한도 안에
들어갑니다 — 한 달이 보통 744시간 이하이기 때문입니다.)

1. https://uptimerobot.com 같은 무료 핑 서비스에 가입
2. 새 모니터(Monitor) 추가:
   - Monitor Type: HTTP(s)
   - URL: `https://무언가.onrender.com/healthz` (메인 페이지가 아니라 `/healthz`를
     사용하세요 — 비밀번호 없이도 가볍게 응답하도록 만들어둔 경로입니다)
   - Monitoring Interval: 5~10분
3. 저장하면 그 뒤로는 서버가 거의 항상 깨어있는 상태로 유지됩니다.

## 참고
- 구조: Flask(웹서버) + yt-dlp(추출) + ffmpeg(영상/음성 변환, Dockerfile에서 자동 설치)
- 서버가 매 요청마다 임시 폴더에 파일을 받았다가 전송 후 자동 삭제합니다.
- 인스타그램이 비공개/스토리 접근 방식을 바꾸거나, yt-dlp 업데이트가 필요해지면
  `requirements.txt`의 `yt-dlp` 버전을 최신으로 올리고 Render에서 재배포하면 됩니다.
- PWA 아이콘/매니페스트는 `static/` 폴더에 있습니다. 더 예쁜 아이콘으로 바꾸고 싶으면
  `static/icon-192.png`, `static/icon-512.png`를 같은 파일명으로 교체하면 됩니다.
